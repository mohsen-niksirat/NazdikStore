**وضعیت فعلی:** API آفلاین `:4000` سالم · فازهای ۱–۱۸ بریف + UI سازمانی پیاده شده · deploy آنلاین برای آخر

## ۱) تحقیق بازار (ایران + هایپرلوکال)

### رقبا / الگوهای محلی
| محصول | الگوی قابل استفاده برای نزدیک استور |
|---|---|
| **اسنپ‌فود / ریحون** | ساعات باز/بسته، زمان تحویل، نقد و نظر، سبد چندفروشنده‌ای ضعیف |
| **اسنپ / تپسی** | رهگیری زنده پیک، ETA، تماس با راننده |
| **دیوار / شیپور** | RFQ محلی، تصویر + شرح، پیشنهاد قیمت |
| **دیجی‌کالا** | کاتالوگ، کد تخفیف، کیف پول، پیگیری سفارش |
| **InDrive / Yango** | مزایده قیمت (مثل RFQ ما) |
| **Airbnb / Booking** | تقویم شمسی، بافر نوبت، تعطیلی موقت |

### شکاف‌های ضروری نسبت به «محصول قابل استفاده واقعی»

**A. تکمیل چرخه مشتری (مهم‌ترین)**
- سفارش باید از **سبد → پرداخت → وضعیت → پیام/رهگیری → نظر** یک مسیر واضح باشد
- امروز تکه‌تکه است: cart، track، messages، vendor panel جدا هستند
- **فاکتور/رسید** نداریم
- **کیف پول مشتری** UI نداریم
- **ثبت اختلاف (dispute)** فقط API است

**B. اعتماد و کیفیت داده**
- نظرها در UI مشتری کم‌دیده می‌شوند
- **ساعات کاری فروشنده** (باز/بسته) در نقشه/جستجو نیست
- **آدرس ایرانی** (کوچه/پلاک/نشانی) ساده است
- **تصاویر محصول/پست** pipeline دارد، UI آپلود نه

**C. رشد و حفظ کاربر**
- کد دعوت در تنظیمات هست ولی **صفحه کمپین/جایزه** نیست
- **کارت وفاداری** سمت مشتری فقط در settings ساده است
- **اعلان‌های سفارش** هست ولی «سفارش من» مرکز فرمان نیست

**D. عملیات فروشنده**
- **تعطیل موقت + ساعات** باید روی نوبت/نقشه اثر بگذارد
- **موجودی یک‌جا** (board) هست؛ اتصال به نقشه/feed نه
- **چت سفارش** لینک دارد؛ اعلان پیام جدید badge کم است

**E. فنی / پایداری**
- mini-server در حافظه است → **restart = پاک شدن سفارش‌ها** (باید JSON persist ساده)
- تست‌ها پراکنده → **یک `npm run verify`**
- فونت/RTL آفلاین (Vazirmatn CDN ممکن است نیاید)
- Lighthouse a11y: ARIA روی تب/کارت‌ها

**F. امنیت و انطباق**
- `dev-login` فقط در production خاموش می‌شود — **پیام UI برای demo mode**
- OTP در ترمینال — **مرحله SMS واقعی در deploy**
- حریم خصوصی مکان خانگی خوب است؛ باید در FAQ مشتری توضیح داده شود
